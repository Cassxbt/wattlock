How it works

Settlement must see the allocation it pays for.

WattLock turns a certificate reservation into a narrow cross-chain authorization. The source creates the lock. Attestcoin proves it. CC3 pays only after every bound field matches.

The exact mechanism

RESERVE → PROVE → LOCK → SETTLE → BLOCK → VERIFY

Each step exists to close one failure mode. No administrator selects a winner. No UI assertion releases the escrow.

A job moves through five checks

One allocation can settle one exact job.

Sepolia

Certificate owner reserves the allocation

DemoCertificateIssuer emits one CertificateReserved event. It binds a certificate ID, job ID, allocation hash, owner, energy amount, expiry, and source chain.

CC3

Buyer opens a fixed compute job escrow

The CC3 job fixes the provider, reward, required energy, and settlement deadline before the allocation commitment is created.

Attestcoin

The source receipt becomes verifiable settlement input

settleWithProof pins the source to Sepolia Attestcoin key 1, then invokes native proof verification.

WattLock

The receipt must describe this exact allocation

The contract validates the issuer, event shape, transaction success, certificate owner, energy, expiry, allocation hash, and job status. One mismatch reverts.

Settlement

Escrow pays once or the certificate is refused

The provider receives the fixed test-CTC escrow atomically. A reused source certificate fails with CertificateAlreadyReserved().

What the hash binds

Certificate, job, buyer, provider, reward, energy, deadline, CC3 chain, and WattLock contract.

It is not a reusable green credential.

What is intentionally absent

No token, marketplace, fractional allocation, hardware oracle, or carbon accounting layer.

Version one proves the one-certificate, one-job gate first.
